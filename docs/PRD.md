## 1. BLUF（一段话说清）

NEON DODGE v1.1 已经能玩，但没有「回来的理由」。v3.0 先建**度量地基**（埋点 + 统计面板），再加三条留存钩子：难度档位、每日挑战、进步可见；最后用道具磁吸降低新手挫败。

- **北极星**：D2 次日回访 ≥ 25%（DAU ≥ 30 才采信）。
- **不做什么**：在线排行榜、账号、内购、关卡。
- **最大风险**：0 用户、0 埋点，所有目标值目前都是假设。

### 2.1 背景与事实

### 2.2 用户痛点（按严重度）

1. **新手第一局常常一次擦身都没触发**就结束——没体验到核心卖点就流失；
2. **老手没有目标**：通关后只能刷分，缺少「今天的挑战」这种确定性任务；
3. **改版无法验证**：没有本地统计，调参靠感觉；
4. **道具像装饰**：拾取率约 0.8，设计预期 ≥ 2。

### 2.3 Scope

| 类别 | 内容 |
| :--- | :--- |
| In scope | 单机玩法、本地数据、难度档位、每日挑战、分档榜单、统计面板、道具磁吸 |
| Out of scope | 服务端、账号、社交、商业化、关卡剧情 |
| Assumptions | 用户多来自移动端分享；单次会话 ≤ 3 分钟；无服务器预算 |
| Dependencies | GitHub Pages、`localStorage`、Vibration API（缺失则降级） |

## 3. Goals / Non-Goals / Anti-Goals

### 3.1 Goals（假设值，待基线校准）

| # | 目标 | 可测结果 |
| :--- | :--- | :--- |
| G0 | **北极星**：愿意回来 | D2 回访 ≥ 25%（DAU ≥ 30 采信） |
| G1 | 新手首局体验到核心卖点 | 首局擦身 ≥ 1 次 ≥ 80%；首局拾取 ≥ 1 道具 ≥ 60%；首局存活 ≥ 25s ≥ 50% |
| G2 | 老手有每日目标 | 挑战参与率 ≥ 25%；完成率 ≥ 60% |
| G3 | 进步可见 | 面板可导出 schema JSON；7 天基线完整率 ≥ 95% |
| G4 | 道具不再像装饰 | 单局拾取 ≥ 1.5 |

### 3.2 Non-Goals

| 不做 | 原因 |
| :--- | :--- |
| 在线排行榜 | 需后端与反作弊，当前无预算 |
| 账号 / 云存档 | 违背「打开即玩」 |
| 内购 / 广告 | 无商业化目标 |
| 关卡 / 剧情 | 街机循环即内容 |
| 局中存档 | 成本高于收益（Q2） |

### 3.3 Anti-Goals（做了会更糟）

无限磁吸 · 自动拾取 · 每日签到弹窗 · 付费复活 · 每日挑战可重试。

## 4. Users and Use Cases

| Persona | Use case | 优先级 |
| :--- | :--- | :--- |
| 新手 | 打开链接 → 30 秒内理解规则 → 首局至少擦身一次 | P0 |
| 常驻 | 每天打开 → 玩一局每日挑战 → 看排名 | P0 |
| 硬核 | 选硬核档 → 冲高分 → 榜单留名 | P1 |

**用户故事**

- 作为新手，我希望第一次玩就知道「贴边过去能加分」，才知道自己在追求什么。
- 作为常驻玩家，我希望每天有一局固定的挑战，和别人比的是同一局。
- 作为硬核玩家，我希望难度能调高，否则高分没有含金量。

## 5. Requirements

### 5.1 现状基线（v1.1，验收不得回归）

| ID | 给定 | 当 | 则 |
| :--- | :--- | :--- | :--- |

| B10 | 刷新页面 | 重载 | 本局丢失，最高分与榜单保留 |

### 5.2 P0 功能

| ID | 需求 | 验收（Given/When/Then） |
| :--- | :--- | :--- |
| F1 | 难度档位 0.8× / 1.0× / 1.25× | 给定档位，障碍初速与加速度按系数缩放；局中不可切换；记忆到下次 |
| F2 | 分档榜单 | 每档独立 8 条；切档只显示该档；不迁移历史；空榜有引导文案 |
| F3 | 每日挑战 | 本地日期（UTC+8）为 seed；**固定标准档**；独立榜；**每期仅 1 次**；连胜仅展示 |
| F4 | 道具磁吸 | 净距 ≤ r 时道具 3× 速度靠拢；`r(t)=0.08W+0.10W·max(0,1−t/150)`（t=局内秒，W=屏宽）；硬核恒 0 |
| F5 | 统计面板 | 总局数 / 最高分 / 平均存活 / 拾取率 / 档位占比 / 挑战完成率；导出附录 A schema |
| F6 | 首局引导 | 前 5 秒显示「← → 移动」，移动即消失；不弹窗、不阻塞 |

## 6. Design Overview

### 6.1 循环

```
menu → playing → over → playing
  └→ daily（锁标准档、仅 1 次）→ over
playing ⇄ paused
```

### 6.2 数据模型

| 键 | 内容 | 版本 |
| :--- | :--- | :--- |
| `nd:v2:meta` | `{schema:1, migratedFrom, at}` | v1 |
| `nd:v2:stats` | 聚合指标 | v1 |
| `nd:v2:events` | 环形缓冲 ≤ 500 条 | v1 |
| `nd:v2:settings` | 档位、静音、音量 | v1 |

### 6.3 关键机制

- **磁吸**：仅对道具生效，半径随局内时间线性衰减；硬核恒 0（四点边界单测）。
- **每日挑战**：`seed = hash(UTC+8 日期)`；与自由模式共用引擎，仅模式标记不同；不计入档位统计。
- **判负与计分**：沿用 v1.1。

### 6.4 边界与异常

| 场景 | 期望行为 | 原因 |
| :--- | :--- | :--- |
| 系统时间被修改 | 按本地日期判定；接受重复挑战 | 本地无防作弊手段 |
| `localStorage` 不可用 / 写满 | 降级内存态，可玩；提示「本次数据不会保存」 | 隐私模式常见 |
| 旧版存档存在 | 按附录 B 迁移；失败则保留旧键 | 不能让老玩家丢榜 |
| 切后台 > 60 秒 | 自动暂停，回来手动继续 | 避免回来即死 |
| 低帧设备（< 40fps） | 降粒子与阴影，逻辑步长不变 | 固定步长保证公平 |
| 多指触摸 | 忽略第二指 | 防误触 |
| 横竖屏切换 | 重排，当局继续 | 不重开 |
| 局中刷新 | 当局丢失，提示「本局未保存」 | 不做中途存档 |
| 挑战中途刷新 | 按开局日结算，不退还次数 | 防反复试错 |
| 音频被拦截 | 静默失败，首次交互后启用 | 浏览器策略 |
| 跨天 00:00 | 进行中的挑战按开局日结算 | 避免跨天作废 |
| `?auto=1` 演示 | 不计入统计与榜单 | 防污染数据 |

## 7. Alternatives Considered

| # | 方案 | 否决原因 |
| :--- | :--- | :--- |
| A1 | 在线排行榜 + 服务端 | 需后端、反作弊与运维；此类街机分数受随机性影响，可比性弱 |
| A2 | 服务端下发挑战 seed | 离线不可用；接受日期 seed 的可作弊代价（R1） |
| A3 | 固定磁吸半径 | 硬核档会变简单；改为随时间衰减 |
| A4 | 磁吸同时作用于障碍 | 改变核心躲避玩法，属另一款游戏 |
| A5 | 档位可局中切换 | 会出现「休闲热身、硬核刷分」，榜单失真 |
| A6 | 每日挑战可重试 | 失败成本归零，可试错摸清种子布局，挑战失去意义 |
| A7 | 接入第三方分析 | 隐私与合规成本；本地面板足以支撑本轮验证 |
| A8 | 自动拾取道具 | 道具变纯数值奖励，「值不值得横移」的决策消失 |

## 8. Cross-cutting Concerns

| 关注点 | 决策 |
| :--- | :--- |
| 隐私 | 零网络请求；事件只写本地；导出由用户触发 |
| 安全 | 无外部输入；`localStorage` 解析 try/catch；不用 `innerHTML` 拼用户数据 |
| 可访问性 | 键盘全操作、焦点可见、`prefers-reduced-motion`、对比度 ≥ 4.5:1 |
| 国际化 | 文案集中管理，默认跟随 `navigator.language`（P2） |
| 可观测性 | 本地事件 + 面板；对外零上报 |
| 成本 | 托管 $0；无服务端；无第三方依赖 |
| 法务 | 代码 MIT；系统字体栈（无第三方字体）；不注册同名商标 |
